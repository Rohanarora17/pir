# EXP-008: Resource-bounded synthetic direct-index PIR scale sweep

Questions: RQ-005 and RQ-008. Claim type: **synthetic result**.

## Question and hypothesis

How do the existing SimplePIR direct-index baseline's setup, communication, local processing and
memory costs change as record count grows? At which tested sizes and reads per snapshot does its
payload-only communication estimate fall below downloading and caching the complete payload once?
A larger database need not favour PIR: setup, matrix reshaping and per-query costs all matter.

## Method, declared before running

Reuse EXP-006's pinned, unmodified IKPIR source and bounded numeric-vector framing. Use the upstream
default SimplePIR LWE dimension 1275 and sigma 6.4, ciphertext modulus 2^32 and 8-bit cells. Check the
upstream correctness bound for each shape. No smaller security setting is offered by this probe.
Use 3,072 and 4,096 byte synthetic rows at 32, 128, 512, 2,048, 8,192, 32,768, 131,072 and 524,288
records. Run 32 sequential reads per admitted case in a separate process, with no precomputed
queries. Include first/last rows, neighbours and deterministic samples across the whole database.
Check every decoded byte against the independently generated expected row.

Rows come from the documented SplitMix64-v1 generator with a fixed public seed. Row and byte
positions determine independent generator inputs. Rows are artificial backend payloads, not repeated
Ethereum proof records. Retain a SHA-256 of each generated byte database. No consensus root,
Ethereum proof verification, real address-map size, proof sharing or update-diversity claim follows.
EXP-006 remains the separate real-proof functional check.

Preflight mirrors the pinned upstream SimplePIR reshape formula without allocating the database.
It checks correctness, the existing message-width limits and a default 1 GiB estimated working-set
budget. The estimate includes the expanded u32 database, two public matrices, two hints, 25% extra
headroom and 64 MiB fixed reserve. It is a conservative admission estimate, not an OS-enforced RSS
limit. Record actual process peak RSS separately. A 180-second timeout bounds each child process.
Retain skipped, failed and timed-out cases instead of silently reducing dimensions or stopping at
only favourable cases. Planned sizes are not a claim that all will fit or run.

Measure setup and local query construction/framing/answer/decode separately. Query/reply bytes are
actual EXP-006 frames. Setup bytes remain upstream canonical minimum estimates plus the 32-byte
binding, with no setup serializer or network transport. Record client public-array bytes separately
from whole-process peak RSS. Report first-read latency and nearest-rank p50/p95 of subsequent reads.
The 31 subsequent samples are exploratory, not a stable throughput benchmark.

Compare communication at 1, 10, 100 and 1,000 reads per immutable snapshot using
`PIR = setup_min + reads * (query + response)` and `cache = database_payload_bytes`.
Do not charge cache download per read. Report the largest integer read count with strictly lower
PIR estimated communication, or none. The estimate is optimistic for PIR because setup is a minimum.
Logical positions are implicit here, so neither path includes a real address map or manifest.
Multiple-generation totals, if shown, are labelled arithmetic full-rebuild models, not measured
Ethereum transitions. Network latency, ordinary RPC timings, other engines, keyword lookup and
real bundled-proof versus shared-node retrieval remain outside this first scale slice.

## Reproduce

From the repository root, using a fresh output directory:

```sh
OUTPUT_DIR=/private/tmp/EXP-008-next sh experiments/EXP-008-synthetic-pir-scale/commands.sh
```

Optional `MEMORY_BUDGET_MIB`, `CASE_TIMEOUT_SECONDS` and `QUERY_COUNT` change resource/sample
budgets, not cryptographic settings. Defaults are 1024, 180 and 32. Existing temporary caches may be
reused through `CARGO_HOME=/private/tmp/pvrpc-verifier-cargo` and
`CARGO_TARGET_DIR=/private/tmp/pvrpc-pir-target`.

This does not freeze ADR-004/005 or complete Day 9's representation comparison. No production code,
protocol schema, source archive or existing retained experiment output is changed.
